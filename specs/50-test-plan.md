# 50 — Как проверить локально

Документ для ручной приёмки: что запустить и что прощёлкать.

---

## Запуск

```bash
cd "/Users/Anton_1/ClaudeProjects/SDDDoctor Lending"
python3 -m http.server 8765
```

Открыть в браузере. **Сборки нет**, правки в файлах видны по F5.

Остановить: `Ctrl+C` в терминале.

## Демо-режим

Пока Supabase не настроен, работает демо-режим: параметр `?mock=1` подменяет базу
на данные в памяти браузера. Продукт щёлкается целиком, включая запись и админку.

Состояние живёт в `localStorage`, поэтому **запись, сделанная на витрине, видна
в кабинете доктора и в админке** — как в настоящей базе.

Внизу экрана фиолетовая плашка «ДЕМО-РЕЖИМ» и кнопка **Сбросить** — возвращает
данные к исходным и стирает вашу запись.

| Роль | Ссылка |
|---|---|
| Участник | http://localhost:8765/index.html?mock=1 |
| Доктор (Аникин) | http://localhost:8765/doctor.html?doc=framework&t=mock-framework&mock=1 |
| Доктор (Харламов) | http://localhost:8765/doctor.html?doc=legacy&t=mock-legacy&mock=1 |
| Админка | http://localhost:8765/admin.html?t=mock-admin&mock=1 |
| Доска зоны | http://localhost:8765/board.html?t=mock-admin&mock=1 |

Без `?mock=1` страницы пойдут в реальный Supabase — пока он не настроен,
увидите баннер «нет связи». Это тоже рабочий сценарий, его проверяем отдельно (блок Е).

## А. Участник — основной путь

1. Открыть витрину. **Смотреть:** четыре карточки, у каждой фото-заглушка с инициалами,
   роль, специализация чипом, описание, номер стола и зелёный бейдж «Свободно N из 6».
2. У Харламова заняты 12:00 и 12:30, а 13:00 заблокирован → бейдж должен показывать
   **«Свободно 3 из 6»**, а не 6.
3. Нажать на карточку Аникина. **Смотреть:** экран слотов, шесть кнопок 12:00–14:30,
   12:00 зачёркнут и подписан «занято».
4. Нажать свободный слот → раскрылась форма. Нажать «Записаться», ничего не заполнив →
   **оба поля краснеют** с подписями.
5. Заполнить имя и команду, записаться. **Смотреть:** экран «Вы записаны» с доктором,
   временем, столом и напоминанием про 5 минут.
6. Нажать «К списку докторов». **Смотреть:** наверху появилась карточка **«Ваша запись»**
   с градиентной рамкой.
7. Зайти к любому другому доктору. **Смотреть:** плашка «У вас уже есть запись к другому
   доктору», все слоты недоступны. Это мягкий лимит — одна запись на устройство.
8. Нажать «Отменить запись» → карточка исчезла, слот снова свободен, бейдж вырос на единицу.

## Б. Участник — крайние случаи

9. Перезагрузить страницу после записи → «Ваша запись» на месте (хранится в браузере).
10. Открыть ссылку стола сразу к доктору: `index.html?mock=1#doctor=context` →
    открывается сразу экран слотов, минуя витрину. Так работают QR на столах.
11. Занять **все шесть** слотов одного доктора (проще из админки — блокировками, см. Г).
    **Смотреть:** карточка гаснет, бейдж серый **«Мест нет»**, карточка не нажимается.
12. Кнопка «назад» в браузере со слотов возвращает на витрину.
13. Проверить на узком экране: DevTools → 360px. Ничего не должно вылезать за края,
    кнопки слотов остаются нажимаемыми пальцем.

## В. Доктор

14. Открыть кабинет Аникина. **Смотреть:** имя, стол, «сегодня приёмов: N»,
    карточки «Сейчас» и «Следующий», расписание на день с именами и командами.
15. Запись, сделанную в пункте 5, видно здесь по имени и команде.
16. Нажать «Заблокировать» на свободном слоте → строка стала «Заблокировано»,
    кнопка сменилась на «Освободить».
17. Вернуться на витрину участника → у этого слота теперь «недоступно», занять нельзя.
18. Открыть кабинет с неверным токеном:
    `doctor.html?doc=legacy&t=неверный&mock=1` → **«Ссылка недействительна»**,
    никаких данных на экране.

## Г. Админка

19. Открыть админку. Вкладка **Доктора** — четыре карточки, у выключенных серый ярлык.
20. «Изменить» у любого → форма с заполненными полями. Идентификатор заблокирован:
    он неизменяем, на нём завязаны ссылка доктора и QR стола.
21. Поменять описание, сохранить → открыть витрину участника, текст обновился **без деплоя**.
22. Переключить «Принимает» в «Нет» → доктор пропал из витрины, но остался в админке.
23. Вкладка **Записи** — все брони по всем столам, отсортированы по времени.
24. «Удалить» у любой записи → подтверждение → строка исчезла, слот освободился у участника.
25. «Экспорт CSV» → файл скачался, открывается в Excel без кракозябр.
26. «Ссылка» у доктора → в буфере персональная ссылка на кабинет.
27. Открыть админку с неверным токеном → **«Доступ запрещён»**.

## Д. Доска зоны

28. Открыть `board.html` на широком экране. **Смотреть:** колонка на каждого активного
    доктора, крупный шрифт, «Сейчас» и список ближайших свободных слотов.
29. Сейчас не 14 сентября, поэтому везде будет «Свободно» — это правильно.
    Чтобы увидеть боевой вид, временно поставьте в `config.js` `DAY` на сегодняшнюю дату
    и окно вокруг текущего часа. **Не забыть вернуть обратно.**

## Е. Поведение без сети

30. Открыть **без** `?mock=1`: http://localhost:8765/index.html
    **Смотреть:** красный баннер «Нет связи с сервером», страница живая, не белый экран.
31. Открыть с `?mock=1`, дать странице загрузиться, затем в DevTools → Network → Offline,
    нажать F5. **Смотреть:** доктора показываются из кэша, бейджи занятости скрыты,
    кнопки записи отключены, баннер объясняет причину.

## Как заводятся доктора

Частый вопрос, поэтому отдельно. Два пути, оба ведут в одну функцию `admin_upsert_doctor`.

### Первый раз — через `seed.sql`

При настройке Supabase выполняется [`supabase/seed.sql`](../supabase/seed.sql).
Он создаёт **четыре заглушки** с id по темам столов: `legacy`, `framework`, `context`,
`adoption`. Имена там буквально написаны «Имя Фамилия — заменить».

Почему id по специализации, а не по фамилии: людей ещё ищем, а темы столов известны.
Когда доктор найдётся — id остаётся прежним, меняется только содержание карточки.
Если переименовать id в фамилию, поедут ссылки докторов и QR столов.

### Дальше — через админку

Открыть `admin.html?t=<токен>` → вкладка **Доктора**:

- **Заменить заглушку:** «Изменить» → вписать реальные имя, должность, специализацию,
  описание, стол → «Сохранить». Готово, участники видят сразу.
- **Добавить пятого:** «+ Добавить» → заполнить, включая идентификатор латиницей.
  Токен доступа для его кабинета создаётся автоматически, забрать кнопкой «Ссылка».
- **Убрать доктора:** переключить «Принимает» в «Нет». Данные и его записи сохранятся.

### Фото

Единственное, что не правится из админки. Кладётся файлом в репозиторий:

```
assets/doctors/<id>.jpg      например assets/doctors/legacy.jpg
```

JPEG, квадрат, минимум 400×400. Имя файла = идентификатор доктора, поля «фото» в форме
нет специально: путь вычисляется из id, поэтому ошибиться негде.
Нет файла — рисуется градиентный аватар с инициалами, страница не ломается.

Добавление фото требует `git push`, всё остальное в карточке — нет.

## Что нельзя проверить локально

| Что | Почему | Когда проверять |
|---|---|---|
| Одновременная запись двух человек на один слот | Нужна настоящая БД с уникальным индексом | После настройки Supabase, две вкладки |
| Что публичный API не отдаёт имён | Нужен реальный endpoint | `curl` после настройки, см. [40-tech-and-deploy.md](40-tech-and-deploy.md) |
| Доступность с телефона на площадке | Мобильная сеть в БКЗ | За день до мероприятия, обязательно |
