## Первичная настройка Supabase

1. Создать проект на supabase.com. Регион — ближайший к РФ (Frankfurt).
2. SQL Editor → выполнить [`supabase/schema.sql`](../supabase/schema.sql).
3. SQL Editor → выполнить [`supabase/seed.sql`](../supabase/seed.sql).
   Последний запрос выведет **ссылки для раздачи** — скопировать их сразу:
   - `admin.html?t=…` — организатору
   - `doctor.html?doc=…&t=…` — каждому доктору
4. Project Settings → API → скопировать `Project URL` и `anon public` ключ
   в [`config.js`](../config.js).

### Про anon key в открытом коде

`anon key` публичен по природе — он лежит в JS любого клиента Supabase.
Безопасность обеспечивается **на стороне БД**, а не сокрытием ключа:

- RLS включён на всех таблицах, политик нет → прямой доступ к таблицам закрыт;
- наружу торчат только `v_doctors` и `v_occupancy` — **без имён и команд**;
- имена доступны только через RPC, проверяющие токен.

Что может сделать посторонний с `anon key`: записаться на свободный слот
(то же, что и любой участник) и создать бронь на странное время внутри дня мероприятия.
И то и другое видно организатору в админке и удаляется в клик.

### Про токены

Токены — случайные 24 hex-символа в таблице `access_tokens`, недоступной анониму.
Паролей нет: внутреннее мероприятие на три часа, секретная ссылка — адекватный уровень.

Ротация: удалить строку из `access_tokens` и пересохранить карточку доктора в админке —
токен сгенерируется заново.

## Деплой

```bash
git add -A && git commit -m "…" && git push
```

GitHub Pages раскатывает сам за 30–60 секунд. **Сборки нет.**

Первичная настройка репозитория:
1. `gh repo create sdd-doctor --public --source=. --push`
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`
3. Файл `.nojekyll` в корне обязателен — иначе Jekyll может съесть служебные пути.

Адрес: `https://aserzhantov.github.io/sdd-doctor/`

## Что где меняется

| Что | Где | Деплой |
|---|---|---|
| Тексты карточек, стол, вкл/выкл | Админка → БД | Нет |
| Новый доктор | Админка или `seed.sql` | Нет |
| Удалить бронь | Админка → БД | Нет |
| Длина приёма, окно дня, дата | `config.js` | Да |
| Фото доктора | `assets/doctors/<id>.jpg` | Да |
| Цвета и метрика | Токены в `:root` в `assets/styles.css` | Да |

**Фото:** JPEG, квадрат, минимум 400×400, имя файла = `id` доктора.
Нет файла → аватар с инициалами, страница не ломается.

**Смену `SLOT_MINUTES` делать до открытия записи.** Брони хранят абсолютное время;
при смене сетки они станут `off-grid` — показываются отдельной строкой и у участника,
и у доктора, не пропадают, но занять их нельзя.

При переносе даты править `CONFIG.DAY` **и** констрейнт `bookings_event_day`
в `schema.sql` — иначе брони перестанут создаваться.

## QR-коды

```bash
# общий, показывается со сцены
qrencode -o qr/main.png -s 20 -m 4 -l M "https://aserzhantov.github.io/sdd-doctor/"

# на каждый стол — открывает сразу нужного доктора
qrencode -o qr/table-1.png -s 20 -m 4 -l M "https://aserzhantov.github.io/sdd-doctor/#doctor=legacy"

# проверка, что код читается
zbarimg -q --raw qr/main.png
```

Уровень коррекции `M` и `-s 20` проверены на прошлом мероприятии: код читается
с экрана зала и с печатной таблички.

## Чек-лист дня мероприятия

**За неделю**
- [ ] Завести реальных докторов вместо заглушек из `seed.sql`
- [ ] Собрать у докторов описания и фото, положить фото в `assets/doctors/`
- [ ] Разослать докторам их персональные ссылки на `doctor.html`
- [ ] Зафиксировать `SLOT_MINUTES` и окно дня — после этого не менять

**За день**
- [ ] **Открыть лендинг с личного телефона по мобильному интернету на площадке.**
      Проверить и `github.io`, и что запись реально проходит. Это единственная проверка,
      которую нельзя сделать за столом заранее
- [ ] Напечатать таблички на столы: номер, имя доктора, специализация, QR стола
- [ ] Напечатать общий QR для показа со сцены
- [ ] Выгрузить CSV записей и распечатать — офлайн-страховка, если сеть ляжет
- [ ] Проверить `board.html` на том экране или планшете, который будет стоять в зоне

**В день**
- [ ] Показать QR со сцены на открытии и проговорить: **приём только по записи**
- [ ] Дежурный по зоне держит открытым `board.html`
- [ ] Ошибочные брони удаляются организатором в админке

**Если сеть легла**
- Лендинг остаётся живым: показывает докторов из кэша, правила и столы,
  честно пишет, что запись недоступна.
- Работаем по распечатанному CSV: дежурный сверяет по списку.

## Локальная проверка

```bash
python3 -m http.server 8765   # из корня проекта
```

Открыть `http://localhost:8765/`. Работает без сборки, файлы правятся на лету.

Полный список проверок — в конце плана реализации; ключевые:
- две вкладки жмут один слот одновременно → ровно одна бронь, второй видит понятную ошибку;
- `curl` по `anon key` к `v_occupancy` не возвращает имён;
- отключить сеть → страница живая, запись честно сообщает о недоступности;
- ширина 360px, время по МСК корректно при любой таймзоне устройства.
