# 10 — Сценарии и состояния экранов

Четыре роли, четыре страницы. Все времена — **МСК**, независимо от таймзоны устройства.

| Страница | Роль | Доступ |
|---|---|---|
| `index.html` | Участник | Открытый |
| `doctor.html?doc=<id>&t=<token>` | Доктор | Токен доктора |
| `admin.html?t=<token>` | Организатор | Токен админа |
| `board.html?t=<token>` | Дежурный по зоне | Токен админа |

---

## Общие правила

### Генерация сетки слотов

Слоты не хранятся в БД. Считаются на клиенте:

```
начало = doctor.win_start ?? CONFIG.WINDOW.start
конец  = doctor.win_end   ?? CONFIG.WINDOW.end
слоты  = [начало, начало+SLOT, начало+2·SLOT, …] пока slot_end <= конец
```

Каждый слот получает абсолютную метку `slot_start` в МСК на дату `CONFIG.DAY`.
Занятость приходит из `v_occupancy` и матчится по точному `slot_start`.

### Состояния слота

| Состояние | Условие | Вид |
|---|---|---|
| `free` | нет записи, время не прошло | кликабельный, акцентный |
| `taken` | есть `kind='participant'` | приглушён, «занято» |
| `blocked` | есть `kind='blocked'` | приглушён, «недоступно» |
| `past` | `slot_start + SLOT < now` | почти невидим, не кликается |
| `mine` | `id` есть в `localStorage` | подсвечен, «ваша запись» |

**`off-grid`** — бронь из `v_occupancy`, чей `slot_start` не совпал ни с одним слотом сетки.
Возникает, только если `SLOT_MINUTES` или окно поменяли после появления броней. Такая бронь
рендерится отдельной строкой «занято — HH:MM» под сеткой, чтобы не пропасть молча.
Занять её нельзя.

### Мягкий лимит: одна активная запись на устройство

В `localStorage` под ключом `sdd_booking` хранится `{id, cancel_code, doctor_id, slot_start}`.
Если запись уже есть, кнопки бронирования показывают «сначала отмените текущую запись».

**Это ограничение только клиентское** и обходится другим браузером. Серверно опознать устройство
нечем, а вводить регистрацию ради этого — противоречит концепции. Для внутреннего мероприятия
социального давления достаточно; злоупотребление видно организатору в админке и лечится удалением брони.

### Деградация при недоступном Supabase

Ни при каких ошибках сети страница не превращается в белый экран.

1. Успешный ответ `v_doctors` кэшируется в `localStorage` (ключ `sdd_doctors_cache`).
2. Если запрос упал — рисуем докторов из кэша, бейджи занятости скрываем.
3. Наверху баннер: «Запись временно недоступна. Подойдите к столу или попробуйте позже».
4. Кнопки бронирования отключены.
5. Автоповтор запроса каждые 15 секунд, при успехе баннер убирается.

## Сценарий 1 — Участник

### 1.1 Витрина докторов (`index.html`, шаг 1)

**Загрузка:** два запроса параллельно — `v_doctors` и `v_occupancy`.

**Блоки сверху вниз:**
1. Хедер: логотип SDD Day, «Визит к SDD-доктору», дата и место.
2. Плашка правил: **приём только по записи**, длительность, «слот держим 5 минут».
3. «Моя запись» — если в `localStorage` есть бронь: доктор, № стола, время, кнопка «Отменить».
4. Сетка карточек докторов.

**Карточка доктора:**
- фото `assets/doctors/<id>.jpg`; при 404 — градиентный аватар с инициалами
- имя, роль, специализация
- био (2–4 предложения)
- «Стол №N»
- бейдж занятости: `Свободно 4 из 6` / `Остался 1 слот` / `Мест нет`

Карточка с нулём свободных слотов приглушается и не кликается.

**Состояния экрана:**

| Состояние | Что показываем |
|---|---|
| Загрузка | Скелетоны карточек |
| Норма | Витрина |
| Нет активных докторов | «Запись закрыта» + текст «подойдите к столам в зоне» |
| Ошибка сети | Карточки из кэша + баннер, бейджи скрыты |
| Мероприятие завершилось | Баннер «SDD Day завершён, спасибо!», запись отключена |

### 1.2 Слоты доктора (`index.html`, шаг 2)

Открывается по клику на карточку. Реализовано как смена состояния на той же странице
с хэшем `#doctor=<id>` — чтобы работала кнопка «назад» и ссылка со стола вела сразу сюда.

- Шапка: фото, имя, роль, специализация, № стола, кнопка «назад к списку».
- Сетка слотов, сгруппированная по часам.
- Под сеткой — `off-grid` брони, если есть.

Клик по свободному слоту раскрывает форму:
- **Имя** — обязательное, 2–60 символов
- **Команда** — обязательное, 2–80 символов
- Кнопка «Записаться», под ней время и доктор для перепроверки

### 1.3 Отправка записи

Вызов `book_slot(doctor_id, slot_start, name, team)`.

| Результат | Реакция |
|---|---|
| Успех | Сохраняем `{id, cancel_code}` в `localStorage`, экран подтверждения |
| Слот занят (`23505`) | Тост «Этот слот только что заняли», перезагрузка занятости, форма закрывается |
| Доктор неактивен | Тост «Доктор больше не принимает», возврат к витрине |
| Слот вне окна доктора | Тост «Это время недоступно», перезагрузка |
| Сеть/5xx | Тост «Не удалось записаться, попробуйте ещё раз», кнопка активна |

**Экран подтверждения:** «Вы записаны», доктор, № стола, время, напоминание про 5 минут,
кнопки «Отменить запись» и «К списку докторов».

### 1.4 Отмена

Вызов `cancel_booking(id, cancel_code)`. Успех → чистим `localStorage`, обновляем занятость,
тост «Запись отменена». Если брони уже нет (удалил админ) — тоже чистим `localStorage`
и показываем «Запись не найдена, возможно её отменил организатор».

## Сценарий 2 — Доктор (`doctor.html`)

**Вход:** `doctor.html?doc=harlamov&t=<token>`. Ссылку выдаёт организатор.

**Нет параметров или неверный токен:** экран «Ссылка недействительна. Обратитесь к организатору».
Никаких данных не грузим и не показываем.

**Основной экран:**
1. Шапка: имя доктора, № стола, «сегодня N приёмов».
2. **«Сейчас»** — крупная карточка текущего приёма: имя, команда, до какого времени. Если приёма нет — «Свободно».
3. **«Следующий»** — кто и во сколько.
4. Полный список слотов на день: время, статус, имя и команда пациента.
5. У каждого свободного слота — кнопка «Заблокировать», у заблокированного — «Освободить».

**Автообновление** каждые 30 секунд. При ошибке сети — тихий баннер «нет связи, данные от HH:MM»,
последние успешные данные остаются на экране.

Блокировка вызывает `doctor_block_slot(doctor_id, slot_start, token, blocked)`.
Заблокировать занятый участником слот нельзя — кнопки там нет.

## Сценарий 3 — Организатор (`admin.html`)

**Вход:** `admin.html?t=<token>`. Неверный токен → «Доступ запрещён».

Две вкладки.

### Вкладка «Доктора»

Список всех докторов, включая выключенных. У каждого: фото, имя, роль, № стола,
переключатель «Принимает», кнопки «Изменить» и «Ссылка для доктора» (копирует персональную ссылку).

**Форма создания и правки** — одна и та же, вызывает `admin_upsert_doctor`:

| Поле | Обязательное | Примечание |
|---|---|---|
| `id` | да | латиница, только при создании, потом неизменяем — это имя файла фото |
| `name` | да | |
| `role` | нет | должность и команда |
| `specialty` | нет | с чем помогает |
| `bio` | нет | 2–4 предложения |
| `table_no` | нет | номер стола |
| `win_start`, `win_end` | нет | пусто = окно дня из `config.js` |
| `sort` | нет | порядок в витрине |
| `active` | да | по умолчанию включён |

При создании форма показывает подсказку: «Фото положите в `assets/doctors/<id>.jpg` и запушьте.
Без фото будет аватар с инициалами».

**Закрыть запись целиком** = выключить «Принимает» у всех докторов. Отдельной настройки нет.

### Вкладка «Записи»

Все брони по всем докторам, сортировка по времени. Колонки: время, доктор, стол, имя, команда,
тип (запись / блокировка).

- Кнопка **«Удалить»** у каждой строки → `admin_delete_booking`, с подтверждением.
- Кнопка **«Экспорт CSV»** — выгрузка всего списка, файл собирается на клиенте через Blob.

## Сценарий 4 — Дежурный по зоне (`board.html`)

**Вход:** `board.html?t=<admin_token>`. Экран или планшет в практической зоне.

Крупная сетка: колонка на каждого доктора. В колонке — текущий приём (имя, команда, до скольки)
и ближайшие свободные слоты. Автообновление каждые 30 секунд, крупный шрифт, рассчитан на взгляд издалека.

---

## Ссылки со столов

У каждого стола свой QR: `index.html#doctor=<id>` — открывает сразу слоты этого доктора,
минуя витрину. Обработка хэша на загрузке страницы: если `#doctor=<id>` и доктор активен —
сразу шаг 2, иначе витрина.
